# Security policy

## Reporting

Do not disclose vulnerabilities or private screenshots in public issues. Use [GitHub private vulnerability reporting](https://github.com/Osyna/Screnerrr/security/advisories/new) when it is enabled. If that channel is unavailable, open an issue asking for a private security contact without including exploit details, private data or credentials.

Include the affected version, Linux distribution, compositor, reproduction steps and a synthetic input when possible. Do not assume a response deadline or a fixed support period.

## Privacy boundaries

Flattened exports and editable projects have different privacy properties. A `.sharp` project can contain original screenshot pixels beneath redactions. Do not attach a private project to a public report, even when its preview appears redacted. OCR may miss or misread text; inspect the image before sharing it.

Report third-party vulnerabilities upstream as well, identifying the affected dependency and version.
